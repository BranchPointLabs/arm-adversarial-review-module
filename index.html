ARM

Adversarial review for product decisions.

ARM is a local desktop application for Windows, macOS, and Linux. It reviews product ideas, PRDs, RFCs, and plans before code is written.

ARM does not generate giant documents. It works against the document you already have and returns small critique cards: risks, contradictions, questions, scope cuts, actions, and decision candidates.

You accept, reject, or edit each card. Changes stay explicit, reviewable, and user-approved.

ARM vs BMAD

BMAD optimizes for generated output. ARM optimizes for controlled review.

Area BMAD ARM
Main job Generate large project artifacts through role-based workflows. Review existing documents through small, focused critique cards.
Document model Requires documentation to become comprehensive enough to drive the workflow. Works against the document you already have and pressures the parts that matter.
Output size Produces enough text that reading, evaluating, and reconciling the output becomes its own task. Produces concise cards that can be accepted, rejected, edited, or ignored.
Risk Long outputs can miss key flows, bury weak assumptions, or hide contradictions inside polished prose. Surfaces risks, gaps, contradictions, and open questions directly.
Change control Regeneration can introduce subtle wording changes, meaning changes, or new requirements that are hard to catch. Every proposed change is explicit and requires user approval before it affects the document.
SDLC maintenance Document generation is fast, but maintaining decisions, notes, open questions, and project truth is not the core flow. Supports decisions, notes, open questions, accepted cards, and controlled document updates as first-class workflow pieces.
Auditability High maintenance burden, low auditability: the user must meticulously check large documents for inaccuracies. Smaller review units create a clearer trail of what was challenged, accepted, rejected, or changed.
Optimization Optimizes for speed, coverage, and output. Optimizes for direction, control, correctness, and human judgment.

Start locally

Clone ARM and run the desktop app.

Full setup instructions are in the README.

1. Clone the repository

git clone https://github.com/BranchPointLabs/arm-adversarial-review-module.git
cd arm-adversarial-review-module/arm
npm install

2. Run ARM locally

npm run tauri dev

3. Build a desktop application

Run this on the platform you want to package for: Windows, macOS, or Linux.

npm run tauri build
