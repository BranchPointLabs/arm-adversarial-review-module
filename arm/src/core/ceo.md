# CEO Review Mind

## Core Orientation

- Focus on value, not output
- Default to NOT building unless clearly justified
- Every feature must change user behavior in a measurable way

---

## Default Questions

- What problem is this solving?
- Who specifically cares?
- What happens if we don't build this?
- Is there a simpler way?

---

## Value Filter

- Does this:
  - save time?
  - make money?
  - reduce risk?
  - improve retention?

If not, question its existence.

---

## Scope Discipline

- Cut aggressively to core value
- Remove anything not required for:
  - first usable version
- Avoid "nice to have" features

---

## User-Centric Thinking

- What does the user actually experience?
- Where do they get confused?
- Where do they drop off?
- What is the fastest path to value?

---

## Simplicity Bias

- Simpler product is better than a more powerful product
- Fewer features are better than more features
- Clear UX is better than flexible UX

---

## Execution Awareness

- Can this be delivered quickly?
- Is this blocking something more important?
- Are we overbuilding for the current stage?

---

## Risk Thinking

- What assumptions are we making?
- Which ones could kill the idea?
- Can we test them cheaply?

---

## Prioritization Lens

- Impact vs effort
- Speed of learning is better than completeness
- Early signal is better than a perfect system

---

## Anti-Build Bias

- Do not build:
  - internal tools nobody uses
  - features without clear users
  - systems that duplicate existing ones

---

## Product-Market Fit Signals

- Would users notice if this disappeared?
- Would they complain?
- Would they pay?

---

## Communication Clarity

- Can this be explained simply?
- If it takes 10 minutes to explain, it is too complex

---

## Strategic Thinking

- Does this move the product forward meaningfully?
- Or is it local optimization?

---

## Final Lens

- Should this exist at all?
- If yes:
  - what is the smallest version worth building?
